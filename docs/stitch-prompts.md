## 通用风格约束

以下要求建议追加到每一个 Stitch 提示词末尾，保证视觉统一：

```text
为移动端高保真原型，尺寸参考 iPhone 15 Pro 393x852。
产品名为 gowow，中文界面，风格年轻、有行动感、偏旅行社交，不要做成传统旅游攻略 App。
视觉语言延续现有 demo：白色卡片、圆角大卡片、橙色为主强调色，辅以深灰文字、浅灰背景，局部可用黑色沉浸式头图。
气质参考：小红书的生活方式感 + Tinder 的快速决策感，但更偏“旅行约伴”。
页面要真实可落地，不要过度炫技，不要玻璃拟态堆叠，不要 PC 后台风。
所有文案使用简体中文，信息密度中等，适合路演展示。
输出单页高保真移动端界面，保留底部导航时使用：探索、规划、我的。
```

## 1. 地图探索页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：地图探索页。

页面目标：让用户从首页“推荐流 / 地图”双入口中的“地图”进入后，可以按地点浏览旅行内容和群组线索。

页面结构要求：
1. 顶部为品牌区和双入口切换，保留“推荐流”“地图”两个切换按钮，当前高亮“地图”。
2. 顶部下方保留搜索框，可搜索城市、国家、地点名。
3. 页面主体是地图视图，地图上有多个地点点位，不显示用户实时位置，只显示内容地点。
4. 选中某个点位后，底部弹出一个地点卡片，卡片包含：地点图、地点名、城市、玩法标签、时间标签、内容摘要、主群组人数、加入按钮。
5. 地图上方可以有简洁的筛选 chips，例如：夜市觅食、周末短途、徒步露营、攻略分享、约伴中。
6. 底部保留全局导航：探索、规划、我的，其中探索高亮。

交互气质：
1. 整体要有“在地图上发现真实旅行机会”的感觉。
2. 地图不是工具感很强的导航地图，而是偏生活方式探索地图。
3. 点位点击后，底部浮卡要很精致，像旅行机会卡片。

文案示例：
- 搜索占位：搜索城市、地点、玩法
- 浮卡按钮：查看详情 / 加入群组
- 标签示例：曼谷夜市、周五晚、攻略分享、约伴中
```

## 2. 同兴趣用户页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：同兴趣用户页。

页面目标：用户在对某个地点表达兴趣后，可以快速看到“也喜欢这个地点 / 也想这样玩”的人，判断是否值得进一步了解。

页面结构要求：
1. 顶部返回栏，标题为“同兴趣的人”。
2. 顶部展示当前关联地点的小型信息卡，包含：地点名、地点图缩略图、时间/玩法标签。
3. 主体为用户列表或双列卡片流，每张用户卡片至少包含：头像、昵称、一句话个性签名、旅行标签、最近想去的地方、共同兴趣点。
4. 每张卡片上提供两个轻操作：查看主页、去群里看看。
5. 页面中可以有一个明显的说明区，提示这些人是因为“喜欢同一个地点/玩法”被推荐出来的。
6. 如果需要，可在顶部增加简洁筛选，例如：最近活跃、同城出发、偏攻略型、偏约伴型。

交互气质：
1. 不是婚恋感，不是陌生人社交 App。
2. 更像“这些人也想去这里，你们可能聊得来”。
3. 风格要轻松、可信、带一点行动感。

文案示例：
- 页面说明：这些人也对“曼谷辉煌夜市”感兴趣
- 按钮：查看主页 / 去群里看看
- 标签示例：周末出走、夜市觅食、攻略狂人、摄影记录
```

## 3. 群组页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：群组页。

页面目标：围绕“地点 + 时间/玩法”快速形成轻量旅行群，用户可查看公告、成员、留言并决定是否加入或继续交流。

页面结构要求：
1. 顶部是群组头部区域，包含：群名称、地点、时间、玩法、人数进度（如 128/500）、加入门槛。
2. 头部下方展示群公告，公告信息要醒目但不过度占空间。
3. 再下方是成员预览区，展示部分头像，可点击“查看更多成员”。
4. 主体区域是群留言列表，形式类似轻量聊天/留言墙，消息气泡简洁，偏社群交流而不是 IM 重聊天风格。
5. 未加入时，底部是“申请加入 / 直接加入”按钮；已加入时，底部是留言输入框和发送按钮。
6. 页面内保留一个次级入口：查看群主主页或查看成员主页。

设计重点：
1. 这是小红书群风格的旅行兴趣群，不是企业 IM，也不是微信群截图风。
2. 重点是“轻社群感、真实约伴感、信息可信”。
3. 页面要让人一眼看出这是一个围绕具体地点和时间组织起来的群。

文案示例：
- 群名称：曼谷夜市暴走局
- 公告：本群以周五晚夜市觅食和真实攻略分享为主，广告与无关闲聊会被移除
- 门槛：喜欢该地点即可加入
- 按钮：申请加入 / 直接加入 / 发送
```

## 4. 私聊页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：站内私聊页。

页面目标：用户从群组成员列表或对方主页进入一对一私聊，继续讨论约伴、路线和时间安排。

页面结构要求：
1. 顶部返回栏，展示对方头像、昵称、在线状态或最近活跃时间。
2. 聊天主体为简洁的对话列表，消息以文本为主。
3. 页面中可有一个非常轻的上下文提示条，例如“你们都在 曼谷夜市暴走局 群组中”。
4. 底部是输入框 + 发送按钮，不做复杂语音、图片、表情工具栏。
5. 页面整体要清爽、可信、偏生活方式社交，不做重商务感。

设计重点：
1. 私聊只是群聊后的延展，不是陌生人撩天 App。
2. 视觉上应该让人感觉“继续聊行程安排”，不是泛社交。
3. 可以用一些旅行语境文案来增强真实感。

文案示例：
- 上下文提示：你们都在「曼谷夜市暴走局」群里
- 对话示例：
  - 你周五几点到？
  - 我打算先去辉煌夜市踩点
  - 你更想吃当地小吃还是拍照打卡？
```

## 5. 旅行社交主页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：旅行社交主页。

页面目标：替换当前偏成就系统的个人页，让用户可以快速判断这个人是否适合一起旅行。

页面结构要求：
1. 顶部是用户封面图或旅行感头图，下面是头像、昵称、个人介绍。
2. 显示一组清晰的旅行标签，例如：周末出走、夜市觅食、预算敏感、攻略型、拍照党、轻社交。
3. 展示用户去过的地方或想去的地方，可以是小卡片或横向滚动。
4. 展示该用户发布过的旅行内容缩略卡。
5. 展示该用户参与的群组或最近活跃群组。
6. 页面底部或显著位置提供两个动作：发私聊、查看所在群组。

设计重点：
1. 这是“适不适合同行”的判断页，不是游戏成就页。
2. 要有旅行人格感、真实生活气息和可信度。
3. 信息要让用户快速判断风格是否匹配。

文案示例：
- 个人介绍：喜欢城市夜游和本地小吃，出门前一定做攻略，但现场也愿意临时改计划
- 标签：夜市、轻徒步、攻略控、周末党
- 按钮：发私聊 / 查看群组
```

## 6. 发布内容/发起群组页 Prompt

```text
请为产品「gowow」设计一个移动端高保真页面：发布内容并发起群组页。

页面目标：用户发布一条旅行内容时，可以顺手创建一个“地点 + 时间/玩法”的主群组，降低内容供给和群组供给门槛。

页面结构要求：
1. 顶部返回栏，标题为“发布内容”。
2. 表单区依次包含：地点选择、时间选择、玩法选择、正文输入、图片上传。
3. 页面中有一个明显但不复杂的开关区：是否同时发起群组。
4. 如果开启发起群组，则展开群组配置项：群名称、加入门槛。
5. 页面底部固定主按钮：发布。
6. 视觉上延续当前 demo 的圆角卡片表单风格，但更偏“旅行约伴发布”，弱化打分表单。

设计重点：
1. 当前页面不是写点评，而是发“旅行机会”和“约伴线索”。
2. 保留一点攻略分享气质，但重点是帮助形成群组。
3. 结构清楚，便于用户一眼看懂“发布内容”和“发起群组”可以一起完成。

文案示例：
- 地点：曼谷辉煌夜市
- 时间：本周五 20:00
- 玩法：夜市觅食 / 攻略分享 / 约伴
- 正文占位：分享你的玩法、攻略、踩点建议，或者说明你想找什么样的同行人
- 开关：同时发起群组
- 门槛：喜欢该地点即可加入
```

## 建议生成顺序

如果你要按优先级去 Stitch 里生成，建议顺序如下：

1. 群组页
2. 旅行社交主页
3. 发布内容/发起群组页
4. 地图探索页
5. 私聊页
6. 同兴趣用户页

原因：前 3 个页面最能补齐当前 Demo 的主链路，也最适合高保真路演展示。
